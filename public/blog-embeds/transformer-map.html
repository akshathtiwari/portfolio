A language model is nothing more than a probability distribution over token sequences. Given a vocabulary VVV and a sequence x1:T=(x1,…,xT)x_{1:T}=(x_1,\dots,x_T)x1:T​=(x1​,…,xT​), the chain rule of probability factorizes the joint exactly, with no approximation:

P(x1,…,xT)=∏t=1TP(xt∣x1,…,xt−1)=∏t=1TP(xt∣x<t).P(x_1,\dots,x_T)=\prod_{t=1}^{T} P(x_t \mid x_1,\dots,x_{t-1})=\prod_{t=1}^{T} P(x_t \mid x_{<t}).P(x1​,…,xT​)=t=1∏T​P(xt​∣x1​,…,xt−1​)=t=1∏T​P(xt​∣x<t​).

This left-to-right ordering is the autoregressive factorization. It is a choice of ordering, not of model — but it is the one that lets us both train and sample one token at a time. The only modeling decision is to parameterize each conditional with a neural network, pθ(xt∣x<t)p_\theta(x_t\mid x_{<t})pθ​(xt​∣x<t​), whose final step is a softmax over the vocabulary:

Fitting θ\thetaθ by maximum likelihood means maximizing log⁡Pθ(x1:T)\log P_\theta(x_{1:T})logPθ​(x1:T​), i.e. minimizing the negative log-likelihood (NLL):

Where this goes. The whole rest of the map is engineering to make pθ(xt∣x<t)p_\theta(x_t\mid x_{<t})pθ​(xt​∣x<t​) both accurate and cheap. The softmax head here reappears in weight tying (Embeddings) and every logit is a dot product with a token vector — the seed of attention.

Before a model sees numbers it must cut text into units. Three options sit on a spectrum. Characters give a tiny vocabulary but very long sequences and weak units (attention cost is quadratic in length — Phase 1). Words give short sequences but an unbounded vocabulary and an out-of-vocabulary (OOV) wall. Subwords are the compromise everyone uses: frequent words stay whole, rare words fracture into reusable pieces, and nothing is ever OOV.

Byte-Pair Encoding (BPE), step by step

BPE learns the subword vocabulary greedily from data:

  • Start with a base vocabulary (characters, or the 256 raw bytes).
  • Count every adjacent symbol pair across the corpus.
  • Merge the single most frequent pair into one new symbol; add it to the vocabulary.
  • Repeat for KKK merges. Final vocab size === base + K+\,K+K.

Worked merge: take the corpus low low lower newest widest, split into characters. The pair e s is most frequent (from newest, widest) → merge to es. Now es t is most frequent → merge to est. Next l o → lo, then lo w → low. After four merges, common chunks like low and est are single tokens while rare strings remain splittable.

Byte-level BPE and SentencePiece

Byte-level BPE (GPT-2) runs BPE over the 256 bytes rather than Unicode characters. Because any string is a byte string, there is no <unk> token and every language/emoji is representable. GPT-2's vocabulary is 50,257 = 50,000 merges + 256 bytes + 1 special <|endoftext|>.

SentencePiece / Unigram-LM goes the other way: seed a large candidate vocabulary, fit a unigram language model, and iteratively prune the tokens whose removal least hurts corpus likelihood. It treats input as a raw stream (spaces become a visible ▁), so it is fully reversible and language-agnostic — which is why multilingual models favor it.

Vocab-size tradeoff

A larger vocabulary shortens sequences (cheaper attention, more information per token) but inflates the embedding and softmax matrices, which cost ∣V∣⋅d|V|\cdot d∣V∣⋅d parameters each, and it leaves rare tokens under-trained. Production sizes cluster at 32k–256k.

Why tokenization causes "weird" failures. Digits get chunked inconsistently, so arithmetic is brittle; character-level tasks (reversing a word, "count the r's in strawberry") fight the tokenizer because the model never sees letters; non-English text inflates into more tokens per word; and rare "glitch" tokens that were seen almost never in training can trigger bizarre outputs.

What the dimensions mean

Each token becomes a point in Rd\mathbb{R}^dRd. In an LLM these input vectors are only the starting point — attention then contextualizes them — but even the raw space clusters related tokens.

To feel why the transformer was inevitable, watch the bottleneck move.

n-gram models

An n-gram LM makes a Markov assumption — the next token depends only on the last n−1n-1n−1:

P(xt∣x<t)≈P(xt∣xt−n+1: t−1),P(x_t\mid x_{<t})\approx P(x_t\mid x_{t-n+1:\,t-1}),P(xt​∣x<t​)≈P(xt​∣xt−n+1:t−1​),

estimated by counting and smoothing (Kneser-Ney). It cannot model dependencies longer than nnn, and the count table grows like ∣V∣n|V|^{n}∣V∣n — the curse of dimensionality. Most long n-grams are simply never observed.

RNNs

A recurrent net drops the fixed window by carrying a hidden state:

ht=ϕ(Whht−1+Wxxt+b),h_t=\phi(W_h h_{t-1}+W_x x_t + b),ht​=ϕ(Wh​ht−1​+Wx​xt​+b),

compressing all history into one fixed vector. But training by backprop-through-time repeatedly multiplies by the Jacobian of WhW_hWh​; its singular values shrink or blow up geometrically, giving vanishing / exploding gradients that prevent learning long-range structure.

LSTM / GRU

Gated cells add an additive path for the cell state (the "constant error carousel"): forget, input and output gates decide what to keep. This blunts vanishing gradients and was the workhorse for years — but it is still sequential (no parallelism over time) and still squeezes context through a bounded state.

seq2seq and its bottleneck

Sutskever's seq2seq (2014) encodes a source with one RNN into a single context vector, then decodes with another. The flaw is stark: the entire source sentence must fit in that one fixed vector.

Bahdanau attention — the key idea

Bahdanau (2014) lets the decoder look back at all encoder states through learned alignment weights:

αtj=softmax⁡j(score(st−1,hj)),ct=∑jαtj hj.\alpha_{tj}=\operatorname{softmax}_j\big(\text{score}(s_{t-1},h_j)\big),\qquad c_t=\sum_j \alpha_{tj}\,h_j.αtj​=softmaxj​(score(st−1​,hj​)),ct​=j∑​αtj​hj​.

The fixed-vector bottleneck is gone — but this attention still rides on top of RNNs, so it inherits their sequential, unparallelizable computation.

The 2017 leap. "Attention Is All You Need" keeps the attention and throws away the recurrence. That buys three things at once: full parallelism across the sequence, an O(1)O(1)O(1) path length between any two positions (vs. O(n)O(n)O(n) through an RNN), and far better long-range modeling. Everything in Phase 1 follows.

The autoregressive factorization (Phase 0) demands that the prediction at position ttt depend only on positions ≤t\le t≤t. But self-attention, left alone, lets every token see every other — including the future. Causal masking restores the constraint.

The −∞ mask, applied before softmax

Add a mask to the scaled scores that zeroes out future positions inside the exponent:

Sij′={Sij/dk,j≤i−∞,j>iA=softmax⁡(S′).S'_{ij}=\begin{cases}S_{ij}/\sqrt{d_k}, & j\le i\\[2pt]-\infty, & j>i\end{cases}\qquad A=\operatorname{softmax}(S').Sij′​={Sij​/dk​​,−∞,​j≤ij>i​A=softmax(S′).

Since e−∞=0e^{-\infty}=0e−∞=0, every future weight becomes exactly 0, and the surviving weights still sum to 1. The attention matrix becomes lower-triangular.

Why before the softmax, not after. Masking pre-softmax lets the normalizer sum only over allowed positions, so each row stays a valid distribution. Zeroing entries after softmax would break normalization — the row would no longer sum to 1.

Teacher forcing — why training is one parallel pass

During training we feed the ground-truth prefix rather than the model's own samples ("teacher forcing"). Combined with the causal mask, a single forward pass over a length-nnn sequence computes the next-token loss at every position simultaneously: position ttt predicts token t+1t{+}1t+1, and the mask guarantees it never peeked. This parallel, nnn-losses-per-sequence property is exactly why decoder-only LMs are so efficient to train.

Train vs. inference

The mask is identical at train and inference; only the input source differs. Training uses gold prefixes; generation feeds the model its own samples, so early mistakes compound — exposure bias. At inference we also stop recomputing the triangle: each new token attends to a cache of past keys/values.

Where this goes. That cache is the KV cache (Phase 4) — the reason decode is memory-bound and the target of MQA/GQA, MLA, and KDA.

A single attention head imposes one similarity structure on the sequence. Multi-head attention runs several in parallel, each in its own subspace, so the layer can attend by syntax, by position, and by content at once.

What W_O and the heads do

Empirically, heads specialize: previous-token heads, positional heads, and famously induction heads that detect a repeated pattern ...[A][B]...[A] and copy [B] — the mechanism behind in-context learning.

Deriving the cost

Computing S=QK⊤S=QK^\topS=QK⊤ forms n2n^2n2 entries, each a dkd_kdk​-dimensional dot product, so it costs O(n2d)O(n^2 d)O(n2d) FLOPs; the second matmul AVAVAV costs the same. Storing AAA (per head, per layer) needs O(n2)O(n^2)O(n2) memory:

Contrast the position-wise linear parts (projections, FFN), which are O(n d2)O(n\,d^2)O(nd2). Attention overtakes them once n≳dn\gtrsim dn≳d — precisely the long-context regime everyone wants.

Where it bites: prefill vs. decode

  • Prefill (encode a length-nnn prompt in one pass) is compute-bound and pays the full O(n2d)O(n^2 d)O(n2d).
  • Decode (generate one token, reusing a KV cache) does only O(n d)O(n\,d)O(nd) compute per step but must read the entire O(n d)O(n\,d)O(nd) cache from memory — so it is memory-bandwidth-bound. Over nnn generated tokens the cache-reads total O(n2d)O(n^2 d)O(n2d) again.

Why it drives everything

That n2n^2n2 is the reason long context is expensive, and nearly every architecture line after 2019 is an assault on it, from a different angle:

  • Same FLOPs, less memory traffic: FlashAttention (tiling + online softmax).
  • Shrink the KV that decode must stream: MQA / GQA / MLA.
  • Restrict which pairs interact: sliding-window and sparse attention.
  • Remove the n2n^2n2 term entirely with a recurrent fixed-size state: linear attention, Mamba, and Kimi Delta Attention.

Where this goes. All of Phase 4 is this list, worked out. KDA in Kimi K3 is the endpoint: a hybrid that keeps a little full attention for global recall and makes the rest linear, for ~6× faster decode at 1M tokens.

A deep stack of transformer blocks only trains because of one wiring choice: each block adds its output to its input instead of replacing it. With pre-norm, block lll computes

where FlF_lFl​ is either the attention or the FFN sub-layer. Unrolling the whole stack gives the residual stream view:

The final state is the input embedding plus the sum of every block's contribution. Read the stream as a shared communication bus of width ddd: each sub-layer reads a subspace, computes something, and writes an additive update back. Nothing is overwritten; information persists by default.

Why gradients survive depth

Differentiate one block:

The core problem, and relative schemes

FlashAttention is the realization that attention is memory-bandwidth bound, not compute bound. The naive kernel writes the n×nn\times nn×n score matrix SSS to HBM, reads it back for softmax, writes AAA, and reads it again for AVAVAV — all O(n2)O(n^2)O(n2) HBM traffic, while the matmuls themselves are cheap by comparison.

HBM vs SRAM, and tiling

A GPU has large-but-slow HBM (~TB/s) and tiny-but-fast on-chip SRAM (~tens of MB, ~10× the bandwidth). FlashAttention keeps the n×nn\times nn×n matrix out of HBM entirely: it streams K,VK,VK,V in blocks into SRAM and accumulates the output block by block, never materializing a full attention row.

Kimi Delta Attention (the Kimi Linear paper) extends Gated DeltaNet with two moves that make linear attention finally competitive with full attention.

1 — Channel-wise forget gates

Rather than one scalar decay per head, KDA learns a separate forget gate per feature channel of the state, so each dimension of memory retains or forgets independently — much finer control over what the recurrent state keeps.

2 — DPLR transitions, computed chunkwise

The state update takes the form Si=AiSi−1+ϕ(ki)vi⊤S_i=A_i S_{i-1}+\phi(k_i)v_i^\topSi​=Ai​Si−1​+ϕ(ki​)vi⊤​ where the transition AiA_iAi​ is Diagonal-Plus-Low-Rank: a diagonal part (the channel-wise decay) plus a low-rank correction (the delta-rule removal term). DPLR is expressive yet admits a chunkwise-parallel algorithm — parallel like attention within a chunk, recurrent like an RNN across chunks — so training is hardware-efficient rather than strictly sequential.

The hybrid, and the 6× number

Kimi K3 interleaves KDA and full-attention layers at a 3:1 ratio. The three KDA layers carry the bulk cheaply — O(1)O(1)O(1) per-step cost, a tiny fixed state, and no growing KV cache — while the one full-attention layer restores the exact global recall the linear layers give up. Kimi Linear showed this hybrid beats pure full attention under a fair comparison.

Why ~6× faster decode at 1M. At million-token context, full attention is dominated by streaming its enormous KV cache from HBM every step. In the hybrid, only 1 layer in 4 pays that cost; the KDA layers stream nothing. Memory traffic — the decode bottleneck from the KV-cache card — collapses.

Where this ends. This closes the war on O(n2)O(n^2)O(n2) opened in Phase 1: three-quarters of the model is recurrent-linear, quality is held by the hybrid, and the central villain is finally, mostly, retired.

A Mixture-of-Experts layer replaces the single FFN with NNN expert FFNs E1,…,ENE_1,\dots,E_NE1​,…,EN​ and a small router that decides which experts each token uses. The router scores experts and a softmax turns scores into weights:

This is the key trick: total parameters scale with NNN (all experts exist and hold knowledge), but active compute per token scales with kkk (only kkk experts run). You buy capacity without buying proportional FLOPs.

Capacity and token dropping

Where this goes. Nothing here stops the router from collapsing onto a few favorite experts — the balancing problem, next.

Left unconstrained, routers collapse: a few experts win early, receive more tokens, improve faster, and win more — rich-get-richer. The result is wasted capacity and lopsided per-device compute. Three generations of fixes:

Auxiliary load-balancing loss

Let fif_ifi​ be the fraction of tokens routed to expert iii and PiP_iPi​ the mean router probability for expert iii. Add

to the language-model loss. It is minimized at uniform load, pushing the router to spread tokens. The cost: it competes with the LM objective — a gradient tug-of-war.

Auxiliary-loss-free (DeepSeek-V3)

Instead of a loss, add a per-expert bias bib_ibi​ to the scores used for selection only (not to the gate weight), and adjust it online — raise bib_ibi​ for under-used experts, lower it for over-used ones. Balance is achieved with no extra gradient interfering with the LM objective.

Quantile Balancing (Kimi K3)

K3 derives each expert's allocation from the quantiles of the router-score distribution — routing by where a token's score falls in that distribution — which holds balance even at the extreme 16-of-896 sparsity where simple bias-nudging becomes fragile.

Where this goes. Balancing gets harder as experts get smaller and more numerous — the fine-grained trend, next.

DeepSeekMoE refined the vanilla MoE layer with two ideas now standard on the efficient frontier.

Fine-grained experts

Split each expert into several smaller ones and route more of them (larger kkk). With NNN smaller experts choosing kkk, the number of expert combinations a token can express, (Nk)\binom{N}{k}(kN​), grows sharply — more specialization per parameter, at the same active FLOPs.

Shared experts

Designate a few always-on shared experts that every token passes through, so common, general-purpose computation lives there and the routed experts are freed to specialize rather than each re-learning the basics.

Cost: expert parallelism

Experts are spread across devices, so routing requires an all-to-all exchange — send each token to its experts' devices, then gather the results back. This communication is the dominant MoE overhead and is overlapped with compute.

The sparsity trend. Mixtral 2-of-8 → DeepSeek-V3 8-of-256 → Kimi K2 8-of-384 → K3 16-of-896. The active/total ratio keeps shrinking: more total knowledge at roughly fixed active compute — but routing and optimization become first-order problems, which is what the next card is about.

Where this goes. Pushing to 16-of-896 needs a stability framework — Stable LatentMoE.

At Kimi K3's extreme sparsity — 16 experts chosen from 896 — the things that were second-order at Mixtral scale become first-order. Each expert sees a tiny slice of every batch, so per-expert gradients are noisier; load balance is fragile; and routing decisions dominate optimization dynamics. Stable LatentMoE is K3's framework for keeping training stable in this regime, and it is tied to the reported ~2.5× scaling-efficiency gain over K2.

Why sparsity destabilizes

  • Routing is optimization: with 896 experts, small router changes reshuffle which experts learn what, so router and experts must co-adapt without oscillating.
  • Statistics thin out: a fixed batch spread over 896 experts leaves few tokens each, raising gradient variance and making balancing (see Quantile Balancing) essential rather than optional.

Beyond Chinchilla

Chinchilla optimizes training compute. For deployment, inference cost dominates, so it pays to over-train a smaller model far past 20:1 (Llama trains 7–8B models on trillions of tokens) to get a cheaper-to-serve model at equal quality. When data is the binding constraint, repeating it has diminishing returns (roughly up to ~4 epochs of value), which reshapes the optimal NNN–DDD trade.

Where this goes. Those tokens have to come from somewhere and be clean — the data pipeline, next.

Frontier pretraining data is a multi-stage pipeline, and quality dominates quantity.

  • Crawl & extract: web dumps (CommonCrawl) → clean text extraction.
  • Deduplicate: exact plus fuzzy near-dup removal via MinHash + LSH. Dedup reduces memorization and, per unique token, improves generalization.
  • Quality-filter: lightweight classifiers (score "reference-like" text), heuristics (symbol/word ratios, length), and perplexity filters drop junk.
  • Mixture & annealing: weight domains (web / code / math / books), then run a final high-quality decay phase that upweights math, code, and curated data to sharpen the model near the end of training.
  • Synthetic data: model-generated rephrasings, textbook-style content, and reasoning traces increasingly supplement the crawl.
Case studies. Llama 3 (~15T tokens, aggressive filtering + annealing) and DeepSeek-V3 (~14.8T tokens, math/code-heavy) are the canonical public recipes; both lean on dedup, classifier filtering, and a late high-quality phase.

Where this goes. QK-clip is a stability fix — the theme of the last card in this phase. First, the precision it all runs in.

Lower precision means less memory and bandwidth — if you control the numerics.

  • FP16: half the bytes but a narrow exponent range, so small gradients underflow. Loss scaling multiplies the loss by SSS before backprop and divides by SSS before the update, shifting gradients into the representable range.
  • BF16: keeps FP32's exponent range with fewer mantissa bits, so no loss scaling is needed — robust, and the modern default.
  • FP8 (DeepSeek-V3): 8-bit matmuls with fine-grained per-tile scaling to fit the dynamic range — a large speed and memory win at scale.
  • MX block formats: "microscaling" — a block of KKK elements shares one scale factor (MXFP8, MXFP4), an open standard that makes very low precision practical.
K3's QAT. Kimi K3 trains quantization-aware in MXFP4 weights and MXFP8 activations — so the model learns to be robust to 4-bit weights during training, rather than being quantized after the fact — and can then be served in FP4 with minimal quality loss.

Where this goes. Doing all this across thousands of chips is the parallelism problem, next.

A trillion-parameter run is split many ways at once.

  • Data parallel + ZeRO/FSDP: replicate the model, split the batch, all-reduce gradients. ZeRO shards optimizer states (stage 1), gradients (stage 2), then parameters (stage 3 / FSDP) across data-parallel ranks, gathering parameters just in time — so per-device memory falls with the number of ranks.
  • Tensor parallel (Megatron): split individual matmuls across devices. Pairing a column-split weight AAA with a row-split weight BBB in Y=(XA)BY=(XA)BY=(XA)B needs just one all-reduce per block.
  • Pipeline parallel: split layers into stages; pipeline microbatches through them. The idle "bubble" is ≈p−1m\approx \dfrac{p-1}{m}≈mp−1​ for ppp stages and mmm microbatches — shrunk by using many microbatches and interleaved schedules.
  • Expert parallel: distribute MoE experts with all-to-all routing (Phase 5). Context/sequence parallel: split the sequence dimension for long context.

A real layout composes these (DP×TP×PP×EP) around the network: tensor parallel within a node over fast NVLink, pipeline and data parallel across nodes where bandwidth is scarcer.

Where this goes. Even a perfect layout diverges without stability engineering — the final card.

At frontier scale, instability is a first-class engineering problem, not an afterthought.

  • Loss spikes: abrupt loss jumps from a bad batch, too-high LR, or numerics — a spike can permanently derail a run.
  • Logit explosion: attention or output logits grow unbounded toward NaN. QK-norm and QK-clip cap or rescale the query/key path to prevent it (the exact reason MuonClip exists, Phase 6 optimizers).
  • z-loss: regularize the softmax log-partition toward zero, Lz=λ(log⁡∑vezv)2,\mathcal{L}_z=\lambda\Big(\log\sum_{v} e^{z_v}\Big)^2,Lz​=λ(logv∑​ezv​)2, keeping logits bounded and the softmax well-conditioned.
  • muP: the maximal-update parameterization scales initialization and per-layer learning rates by width so that optimal hyperparameters transfer from a small proxy model to the full run — tune cheaply, apply at scale.
  • Monitoring & restart: watch the gradient norm (spikes foreshadow divergence), checkpoint often, and on divergence roll back and skip or reshuffle the offending data.

Where this goes. A stable base model is only half the story — turning it into an assistant and a reasoner is Phase 7.

Supervised fine-tuning turns a base model into an instruction follower. Format each example with a chat template — special role tokens marking user and assistant turns — and train with the ordinary next-token loss, but mask it so gradients come only from the assistant tokens. The model learns to produce responses, not to predict the prompt.

Where this goes. Point the same RL machinery at tools and long horizons and you get agents — the last card of this phase.

Agentic post-training turns a chat model into something that acts over many steps.

  • Tool calling: a structured format (function-call / JSON tokens) lets the model emit a call, receive the result, and continue — the basic act–observe loop.
  • Long-horizon RL: reward often lands only at the end of a trajectory (task solved, tests pass), so credit must be assigned across many turns and tool calls — the hard part of agentic RL.
  • Environments & verifiers: sandboxed code execution, browsers, and task simulators supply programmatic reward. The fidelity of the environment and verifier bounds what the agent can learn — a well-designed verifier is as important as the algorithm.
This is the explicit training focus behind Kimi K2/K3-style agentic models: coding agents and long-horizon tasks, trained in verifiable environments.

Where this goes. A trained model still has to be served fast and cheap — Phase 8, your home turf.

Serving has two phases with opposite bottlenecks, and the deciding quantity is arithmetic intensity I=FLOPs/bytes movedI=\text{FLOPs}/\text{bytes moved}I=FLOPs/bytes moved. A device is compute-bound when III exceeds its ridge point I\*=peak FLOP/speak byte/sI^\*=\dfrac{\text{peak FLOP/s}}{\text{peak byte/s}}I\*=peak byte/speak FLOP/s​, and memory-bound below it.

  • Prefill processes the whole nnn-token prompt in parallel — large matmuls, high III → compute-bound. It sets TTFT (time to first token) and pays the O(n2)O(n^2)O(n2) attention.
  • Decode emits one token at a time reusing the KV cache — a tiny matmul that must still read all the weights and the whole cache, so III is low → memory-bandwidth-bound. It sets TPOT (time per output token).
Consequences. Chunked prefill splits a long prompt and interleaves it with decode steps to keep latency bounded and the GPU busy. Prefill/decode disaggregation runs the two phases on separate GPU pools, since their optimal batch sizes and parallelism differ.

Where this goes. Exploiting these regimes across many concurrent requests is the job of the serving system, next.

Throughput comes from how the KV cache and the batch are managed.

  • Continuous batching (Orca): add and remove sequences from the running batch at token granularity, so a finished sequence frees its slot immediately instead of the batch waiting for its slowest member — near-full GPU utilization.
  • PagedAttention (vLLM): manage the KV cache like OS virtual memory — fixed-size blocks (pages), allocated on demand and non-contiguous. This eliminates fragmentation and enables sharing via copy-on-write for parallel samples, pushing memory waste toward zero.
  • RadixAttention (SGLang): store cached prefixes in a radix tree so shared prompt prefixes — system prompts, few-shot examples — reuse KV across requests and skip recomputation.
  • KV offloading: spill cold cache to host memory (or disk) under pressure and page it back on demand.

Where this goes. Beyond scheduling, you can change the decode algorithm itself — speculative decoding, next.

Because decode is memory-bound, verifying kkk tokens costs almost the same as generating one (the weights are read once regardless). Speculative decoding exploits this: a cheap draft proposes several tokens, the target verifies them in a single parallel pass, and the longest correct prefix is accepted.

Why it is lossless

Rejection sampling makes the accepted tokens follow the target distribution exactly. With target ppp and draft qqq, accept a drafted token with probability

α=min⁡ ⁣(1,p(x)q(x)),\alpha=\min\!\Big(1,\frac{p(x)}{q(x)}\Big),α=min(1,q(x)p(x)​),

and on rejection resample from the residual ∝max⁡ ⁣(0, p(x)−q(x))\propto\max\!\big(0,\,p(x)-q(x)\big)∝max(0,p(x)−q(x)). The resulting samples are distributed as ppp — so quality is provably unchanged; only speed improves.

The family

Drafters range from a small separate model, to Medusa (extra heads predicting several future tokens, no separate model), to EAGLE 1/2/3 (drafting at the feature level — predicting the target's next hidden state — for much higher acceptance), verified over a tree of candidate continuations rather than a single chain.

DFlash and DSpark sit at the frontier of this taxonomy: block-diffusion drafting that fills a whole block in one parallel pass with target-feature-injected conditioning, pushing acceptance and speedup past sequential EAGLE-style drafters.

Where this goes. MTP (two cards on) turns the model's own training heads into exactly this kind of drafter.

Post-training quantization compresses an already-trained model to low bit-width. The recurring enemy is outliers.

  • INT8 + outliers (LLM.int8): a few activation dimensions carry huge magnitudes that wreck naive INT8; keep those dimensions in FP16 and quantize the rest to INT8 (mixed-precision decomposition).
  • GPTQ: quantize weights using second-order (Hessian) information — process weights one at a time and update the remaining ones to compensate for the induced error — reaching ~4-bit with little degradation.
  • AWQ: activation-aware — identify the salient weight channels (those multiplied by large activations) and protect them with per-channel scaling before quantizing; no backprop required.
  • FP4 / MX: 4-bit microscaling formats with a block-shared scale.
  • KV-cache quantization: quantize the cache itself (FP8/INT4), attacking the decode memory bottleneck (Phase 4) directly.

The trade is always bits vs. quality; weight-only is easier than quantizing activations too.

Where this goes. K3 sidesteps most PTQ loss by training in MXFP4 from the start (Phase 6 precision).

Multi-Token Prediction adds auxiliary heads that predict the next several tokens during training, not just the immediate next one (DeepSeek-V3, Kimi K2/K3 lineage). The denser objective improves the learned representations at no inference cost by itself.

Heads as a built-in drafter

At inference those same MTP heads double as a self-speculative drafter: they propose the next few tokens, which the main model verifies in one pass (the speculative-decoding machinery from two cards ago) — with no separate draft model to train or host. Measured acceptance rates translate into roughly a ∼ ⁣1.8×\sim\!1.8\times∼1.8× decode speedup.

Where this goes. The last card scales all of this to a trillion-parameter MoE at million-token context.

Serving a trillion-parameter MoE is a distributed-systems problem on top of everything above.

  • Expert-parallel inference: experts are spread across many accelerators; each token is routed to its experts' devices via all-to-all, which is overlapped with compute to hide the communication.
  • Wide-EP / supernodes: treat 64+ accelerators as one unit (recommended for Kimi K3) so the full expert set fits and the all-to-all runs over a fast intra-node fabric.
  • Hybrid linear attention changes the memory equation: at 1M-token context a full-attention KV cache would be prohibitive, but KDA layers (Phase 4) carry only a fixed-size state — so the bulk of the model streams no cache, and million-token serving becomes feasible.

Kimi Linear (late 2025) is the bridge paper to K3. It is the point where the entire linear-attention lineage (linear attention → gating → Mamba → DeltaNet → Gated DeltaNet → KDA) finally pays off against softmax attention.

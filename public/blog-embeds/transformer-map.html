A language model is nothing more than a probability distribution over token sequences. Given a vocabulary $V$ and a sequence $x_{1:T}=(x_1,\dots,x_T)$, the chain rule of probability factorizes the joint exactly, with no approximation:

$$P(x_1,\dots,x_T)=\prod_{t=1}^{T} P(x_t \mid x_1,\dots,x_{t-1})=\prod_{t=1}^{T} P(x_t \mid x_{This left-to-right ordering is the autoregressive factorization. It is a choice of ordering, not of model — but it is the one that lets us both train and sample one token at a time. The only modeling decision is to parameterize each conditional with a neural network, $p_\theta(x_t\mid x_{ $$p_\theta(v\mid x_{where $z_t\in\mathbb{R}^{|V|}$ are the logits at position $t$.

From maximum likelihood to cross-entropy

Fitting $\theta$ by maximum likelihood means maximizing $\log P_\theta(x_{1:T})$, i.e. minimizing the negative log-likelihood (NLL):

$$\mathcal{L}(\theta)=-\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{Each term is exactly the cross-entropy between the one-hot target $e_{x_t}$ and the predicted distribution, because the target puts all its mass on the true token:

$$H(e_{x_t},p_\theta)=-\sum_{v\in V}\mathbf{1}[v=x_t]\,\log p_\theta(v\mid x_{So "next-token prediction," "maximum likelihood," and "minimize cross-entropy" are three names for the same objective.

Perplexity

Perplexity is the exponentiated average NLL — the standard intrinsic metric:

$$\mathrm{PPL}=\exp\!\Big(\tfrac{1}{T}\sum_{t=1}^{T}-\log p_\theta(x_t\mid x_{It has a clean reading: the effective branching factor the model faces at each step. A model that is perfectly uniform over a size-$|V|$ vocabulary has $\mathrm{PPL}=|V|$; a model that always assigns probability 1 to the truth has $\mathrm{PPL}=1$.

Worked micro-example. Suppose over a 2-token sequence the model assigns probability $0.5$ to each correct token. Average NLL $=-\log 0.5 = 0.693$ nats, so $\mathrm{PPL}=e^{0.693}=2$. In plain words: at every step the model is as uncertain as a fair coin.

Before a model sees numbers it must cut text into units. Three options sit on a spectrum. Characters give a tiny vocabulary but very long sequences and weak units (attention cost is quadratic in length — Phase 1). Words give short sequences but an unbounded vocabulary and an out-of-vocabulary (OOV) wall. Subwords are the compromise everyone uses: frequent words stay whole, rare words fracture into reusable pieces, and nothing is ever OOV.

Byte-Pair Encoding (BPE), step by step

BPE learns the subword vocabulary greedily from data:

  • Start with a base vocabulary (characters, or the 256 raw bytes).
  • Count every adjacent symbol pair across the corpus.
  • Merge the single most frequent pair into one new symbol; add it to the vocabulary.
  • Repeat for $K$ merges. Final vocab size $=$ base $+\,K$.

Worked merge: take the corpus low low lower newest widest, split into characters. The pair e s is most frequent (from newest, widest) → merge to es. Now es t is most frequent → merge to est. Next l o → lo, then lo w → low. After four merges, common chunks like low and est are single tokens while rare strings remain splittable.

Byte-level BPE and SentencePiece

Byte-level BPE (GPT-2) runs BPE over the 256 bytes rather than Unicode characters. Because any string is a byte string, there is no <unk> token and every language/emoji is representable. GPT-2's vocabulary is 50,257 = 50,000 merges + 256 bytes + 1 special <|endoftext|>.

SentencePiece / Unigram-LM goes the other way: seed a large candidate vocabulary, fit a unigram language model, and iteratively prune the tokens whose removal least hurts corpus likelihood. It treats input as a raw stream (spaces become a visible ▁), so it is fully reversible and language-agnostic — which is why multilingual models favor it.

Vocab-size tradeoff

A larger vocabulary shortens sequences (cheaper attention, more information per token) but inflates the embedding and softmax matrices, which cost $|V|\cdot d$ parameters each, and it leaves rare tokens under-trained. Production sizes cluster at 32k–256k.

Why tokenization causes "weird" failures. Digits get chunked inconsistently, so arithmetic is brittle; character-level tasks (reversing a word, "count the r's in strawberry") fight the tokenizer because the model never sees letters; non-English text inflates into more tokens per word; and rare "glitch" tokens that were seen almost never in training can trigger bizarre outputs.

Where this goes. Each token id is about to index a row of the embedding matrix — the next card.

A token id is just an integer. To do math we first turn it into a vector. The naive encoding is one-hot: $x\in\{0,1\}^{|V|}$ with a single 1. One-hot vectors are orthogonal, so they carry no notion of similarity — every token is equidistant from every other.

The embedding matrix is a lookup

Multiply the one-hot by an embedding matrix $E\in\mathbb{R}^{|V|\times d}$:

$$e = E^\top x \in \mathbb{R}^{d}.$$

Because $x$ is one-hot, this matrix-vector product simply selects a row of $E$. So an embedding layer is a learned lookup table: token $v\mapsto E_v$, a dense $d$-dimensional vector. The one-hot framing matters only because it shows the embedding is a linear map — gradients flow to exactly the used row.

What the dimensions mean

Each token becomes a point in $\mathbb{R}^d$. Training shapes this space so that directions and distances encode relationships; the classic intuition is that analogies live in roughly linear directions ($\text{king}-\text{man}+\text{woman}\approx\text{queen}$). In an LLM these input vectors are only the starting point — attention then contextualizes them — but even the raw space clusters related tokens.

The unembedding head, and weight tying

At the output, the final hidden state $h\in\mathbb{R}^d$ is turned back into vocabulary logits by an unembedding matrix $U\in\mathbb{R}^{|V|\times d}$:

$$z = U h,\qquad z_v=\langle h, U_v\rangle,\qquad p=\operatorname{softmax}(z).$$

Every logit is a dot product between the hidden state and a token vector — so decoding is a similarity search in embedding space. Weight tying (Press & Wolf, 2017) sets $U=E$: one matrix serves both input lookup and output scoring. This is principled (both map between token identity and the $d$-space), it regularizes, and it saves a large share of parameters.

Scale check. For GPT-2 (124M), $|V|=50{,}257$ and $d=768$, so $E$ holds $\approx 38.6$M parameters — about 31% of the whole model. Tying input and output embeddings removes a second matrix of the same size.

Where this goes. These per-token vectors are the $X$ that attention will project into queries, keys and values in Phase 1. And the softmax-of-dot-products here is the exact shape of the attention score.

To feel why the transformer was inevitable, watch the bottleneck move.

n-gram models

An n-gram LM makes a Markov assumption — the next token depends only on the last $n-1$:

$$P(x_t\mid x_{estimated by counting and smoothing (Kneser-Ney). It cannot model dependencies longer than $n$, and the count table grows like $|V|^{n}$ — the curse of dimensionality. Most long n-grams are simply never observed.

RNNs

A recurrent net drops the fixed window by carrying a hidden state:

$$h_t=\phi(W_h h_{t-1}+W_x x_t + b),$$

compressing all history into one fixed vector. But training by backprop-through-time repeatedly multiplies by the Jacobian of $W_h$; its singular values shrink or blow up geometrically, giving vanishing / exploding gradients that prevent learning long-range structure.

LSTM / GRU

Gated cells add an additive path for the cell state (the "constant error carousel"): forget, input and output gates decide what to keep. This blunts vanishing gradients and was the workhorse for years — but it is still sequential (no parallelism over time) and still squeezes context through a bounded state.

seq2seq and its bottleneck

Sutskever's seq2seq (2014) encodes a source with one RNN into a single context vector, then decodes with another. The flaw is stark: the entire source sentence must fit in that one fixed vector.

Bahdanau attention — the key idea

Bahdanau (2014) lets the decoder look back at all encoder states through learned alignment weights:

$$\alpha_{tj}=\operatorname{softmax}_j\big(\text{score}(s_{t-1},h_j)\big),\qquad c_t=\sum_j \alpha_{tj}\,h_j.$$

The fixed-vector bottleneck is gone — but this attention still rides on top of RNNs, so it inherits their sequential, unparallelizable computation.

The 2017 leap. "Attention Is All You Need" keeps the attention and throws away the recurrence. That buys three things at once: full parallelism across the sequence, an $O(1)$ path length between any two positions (vs. $O(n)$ through an RNN), and far better long-range modeling. Everything in Phase 1 follows.

Where this goes. Bahdanau's $\alpha_{tj}=\operatorname{softmax}(\text{score})$ becomes self-attention's $\operatorname{softmax}(QK^\top/\sqrt{d_k})$ — same shape, now computed for every position against every other in parallel.

Self-attention lets every token gather information from every other token in a single parallel operation. Start from the token vectors $X\in\mathbb{R}^{n\times d}$ (Phase 0) and make three linear projections:

$$Q=XW_Q,\quad K=XW_K,\quad V=XW_V,\qquad W_Q,W_K\in\mathbb{R}^{d\times d_k},\ W_V\in\mathbb{R}^{d\times d_v}.$$

Read them as roles: the query $q_i$ is "what token $i$ is looking for," the key $k_j$ is "what token $j$ offers as a handle," and the value $v_j$ is "what token $j$ actually contributes."

Scores, scaling, softmax

The affinity of query $i$ to key $j$ is their dot product, $S_{ij}=\langle q_i,k_j\rangle$ — large when the two vectors point the same way, so the dot product is the similarity measure. Collect them as $S=QK^\top\in\mathbb{R}^{n\times n}$, scale, and softmax each row:

$$\operatorname{Attn}(Q,K,V)=\operatorname{softmax}\!\Big(\frac{QK^\top}{\sqrt{d_k}}\Big)V.$$

Each output row is a convex combination of value vectors — token $i$ literally reads a weighted average of everyone's values, weighted by relevance.

Why divide by √d_k — the variance argument

Model the entries of $q$ and $k$ as independent, mean 0, variance 1. A single score is a sum of $d_k$ products:

$$S_{ij}=\sum_{l=1}^{d_k} q_{il}\,k_{jl}.$$

Each term has mean $\mathbb{E}[q_{il}k_{jl}]=0$ and variance $\operatorname{Var}(q_{il}k_{jl})=\mathbb{E}[q_{il}^2]\mathbb{E}[k_{jl}^2]=1$. Independence makes the variances add, so

$$\operatorname{Var}(S_{ij})=d_k,\qquad \operatorname{std}(S_{ij})=\sqrt{d_k}.$$

Raw scores therefore grow like $\sqrt{d_k}$. Feed large-magnitude logits into a softmax and it saturates toward one-hot — and there the gradient dies. The softmax Jacobian is

$$\frac{\partial\,\operatorname{softmax}(z)_i}{\partial z_j}=p_i(\delta_{ij}-p_j),$$

so as some $p_i\to 1$ every derivative $\to 0$. Dividing by $\sqrt{d_k}$ rescales the score variance back to $\approx 1$, keeping softmax in its well-conditioned regime. That single constant is why the whole thing trains.

Worked 3-token example

Let $d_k=2$ and consider the query of token 3, $q_3=[1,0]$, against keys $k_1=[1,0],\,k_2=[0,1],\,k_3=[1,1]$. Raw scores $q_3\!\cdot\!k_j=[\,1,\,0,\,1\,]$; scaled by $1/\sqrt2$: $[0.707,\,0,\,0.707]$. Softmax:

$$\big[\tfrac{e^{0.707}}{Z},\tfrac{e^{0}}{Z},\tfrac{e^{0.707}}{Z}\big]=[0.401,\,0.198,\,0.401],\quad Z=5.056.$$

The output for token 3 is $0.401\,v_1+0.198\,v_2+0.401\,v_3$ — it attends mostly to tokens 1 and 3, whose keys align with its query, and least to token 2.

Where this goes. Add a mask to this (Causal masking), run several in parallel (Multi-head), then notice $S$ is $n\times n$ (Quadratic complexity) — the fact that drives all of Phase 4.

The autoregressive factorization (Phase 0) demands that the prediction at position $t$ depend only on positions $\le t$. But self-attention, left alone, lets every token see every other — including the future. Causal masking restores the constraint.

The −∞ mask, applied before softmax

Add a mask to the scaled scores that zeroes out future positions inside the exponent:

$$S'_{ij}=\begin{cases}S_{ij}/\sqrt{d_k}, & j\le i\\[2pt]-\infty, & j>i\end{cases}\qquad A=\operatorname{softmax}(S').$$

Since $e^{-\infty}=0$, every future weight becomes exactly 0, and the surviving weights still sum to 1. The attention matrix becomes lower-triangular.

Why before the softmax, not after. Masking pre-softmax lets the normalizer sum only over allowed positions, so each row stays a valid distribution. Zeroing entries after softmax would break normalization — the row would no longer sum to 1.

Teacher forcing — why training is one parallel pass

During training we feed the ground-truth prefix rather than the model's own samples ("teacher forcing"). Combined with the causal mask, a single forward pass over a length-$n$ sequence computes the next-token loss at every position simultaneously: position $t$ predicts token $t{+}1$, and the mask guarantees it never peeked. This parallel, $n$-losses-per-sequence property is exactly why decoder-only LMs are so efficient to train.

Train vs. inference

The mask is identical at train and inference; only the input source differs. Training uses gold prefixes; generation feeds the model its own samples, so early mistakes compound — exposure bias. At inference we also stop recomputing the triangle: each new token attends to a cache of past keys/values.

Where this goes. That cache is the KV cache (Phase 4) — the reason decode is memory-bound and the target of MQA/GQA, MLA, and KDA.

A single attention head imposes one similarity structure on the sequence. Multi-head attention runs several in parallel, each in its own subspace, so the layer can attend by syntax, by position, and by content at once.

Splitting into heads

Choose $h$ heads with per-head dimension $d_k=d/h$. Each head $i$ has its own projections and runs ordinary scaled dot-product attention; the outputs are concatenated and mixed by an output projection $W_O\in\mathbb{R}^{d\times d}$:

$$\operatorname{head}_i=\operatorname{Attn}(XW_Q^i,\,XW_K^i,\,XW_V^i),$$ $$\operatorname{MHA}(X)=\operatorname{Concat}(\operatorname{head}_1,\dots,\operatorname{head}_h)\,W_O.$$

Because each head's dimension shrinks by a factor $h$, the total compute is about the same as one full-width head — you get diversity for free.

Exact shapes

  • Input $X:(n,d)$.
  • Per head: $Q,K,V:(n,d_k)$; scores $(n,n)$; head output $(n,d_v)$.
  • Concat over heads: $(n,\,h\cdot d_v)=(n,d)$; after $W_O$: $(n,d)$.
  • Batched with $b$ examples and $h$ heads, the working tensors are $(b,h,n,d_k)$.

What W_O and the heads do

$W_O$ mixes the per-head results back into the shared residual stream (Phase 2); without it, heads would write into disjoint slots and never interact. Empirically, heads specialize: previous-token heads, positional heads, and famously induction heads that detect a repeated pattern ...[A][B]...[A] and copy [B] — the mechanism behind in-context learning.

Parameter count. The four projections $W_Q,W_K,W_V,W_O$ are each $d\times d$, so an attention block holds $4d^2$ parameters — independent of the head count $h$. Choosing $h$ trades many narrow views against fewer wide ones at fixed cost.

Where this goes. Keeping $h$ query heads but sharing K/V across them is exactly MQA/GQA (Phase 4); compressing K/V into a latent is MLA.

One fact organizes the next decade of research. The attention score matrix is $n\times n$.

Deriving the cost

Computing $S=QK^\top$ forms $n^2$ entries, each a $d_k$-dimensional dot product, so it costs $O(n^2 d)$ FLOPs; the second matmul $AV$ costs the same. Storing $A$ (per head, per layer) needs $O(n^2)$ memory:

$$\underbrace{O(n^2 d)}_{\text{compute}}\qquad\underbrace{O(n^2)}_{\text{attention-matrix memory}}.$$

Contrast the position-wise linear parts (projections, FFN), which are $O(n\,d^2)$. Attention overtakes them once $n\gtrsim d$ — precisely the long-context regime everyone wants.

Where it bites: prefill vs. decode

  • Prefill (encode a length-$n$ prompt in one pass) is compute-bound and pays the full $O(n^2 d)$.
  • Decode (generate one token, reusing a KV cache) does only $O(n\,d)$ compute per step but must read the entire $O(n\,d)$ cache from memory — so it is memory-bandwidth-bound. Over $n$ generated tokens the cache-reads total $O(n^2 d)$ again.

Why it drives everything

That $n^2$ is the reason long context is expensive, and nearly every architecture line after 2019 is an assault on it, from a different angle:

  • Same FLOPs, less memory traffic: FlashAttention (tiling + online softmax).
  • Shrink the KV that decode must stream: MQA / GQA / MLA.
  • Restrict which pairs interact: sliding-window and sparse attention.
  • Remove the $n^2$ term entirely with a recurrent fixed-size state: linear attention, Mamba, and Kimi Delta Attention.

Where this goes. All of Phase 4 is this list, worked out. KDA in Kimi K3 is the endpoint: a hybrid that keeps a little full attention for global recall and makes the rest linear, for ~6× faster decode at 1M tokens.

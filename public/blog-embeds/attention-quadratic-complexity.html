Phase 1 · Attention  /  the quadratic wall

Two tokens shake hands. n² is the bill.

Attention's defining move — every token attends to every other — is an all-pairs operation, so its cost is n² by construction. That single fact is the gravitational center of a decade of architecture research: sparse attention, linear attention, FlashAttention, GQA, MLA, state-space models, and Kimi K3 are all different escapes from the same n². Here it is derived exactly, located precisely in prefill and decode, and traced through the field it reshaped.

In 2018, BERT's context window was 512 tokens. By 2026, frontier models advertise context windows of hundreds of thousands to millions of tokens. That progress looks like steady engineering; it was closer to a decade-long siege, and the wall being sieged was a single term in a complexity expression. Doubling the context length does not double attention's cost — it quadruples it. Every long-context capability you now take for granted was paid for by someone finding a way around that quadratic.

The one fact

Self-attention lets every one of nnn positions attend to all nnn positions. That is n2n^2n2 interactions by definition — it is what "attend to everything" means. So attention costs O(n2d)O(n^2 d)O(n2d) compute and O(n2)O(n^2)O(n2) memory, and you cannot make it asymptotically cheaper without changing what attention does: attending to less (sparse), approximating the all-pairs interaction (linear), or merely scheduling it more cleverly (FlashAttention). Nearly every attention paper since 2019 is one of those three moves.

Let's earn that claim: derive both quadratics from the matrix shapes, separate the compute wall from the memory wall (they are attacked differently), locate exactly where each bites during inference, and then read the entire efficiency literature as responses to this one term.

Deriving the O(n²d) compute

Recall scaled dot-product attention on a sequence of nnn tokens with model width ddd. It is three operations, and we just count the arithmetic in each.

1. Scores S=QK⊤S = QK^\topS=QK⊤. Here QQQ is n×dn \times dn×d and K⊤K^\topK⊤ is d×nd \times nd×n, so the product is n×nn \times nn×n. Each of its n2n^2n2 entries is a dot product of length ddd — about ddd multiply-adds. Total:

n2⋅d  =  O(n2d).n^2 \cdot d \;=\; O(n^2 d).n2⋅d=O(n2d).

2. Softmax over each of the nnn rows of the n×nn \times nn×n matrix touches every entry a constant number of times: O(n2)O(n^2)O(n2) — dominated by step 1.

3. Weighted values O=AVO = A VO=AV. The attention matrix AAA is n×nn \times nn×n and VVV is n×dn \times dn×d, giving an n×dn \times dn×d output whose n⋅dn \cdot dn⋅d entries each cost nnn multiply-adds. Total again O(n2d)O(n^2 d)O(n2d).

So one attention layer is O(n2d)O(n^2 d)O(n2d). Multi-head does not change this: the hhh heads split the width into dk=d/hd_k = d/hdk​=d/h, and h⋅n2dk=n2dh \cdot n^2 d_k = n^2 dh⋅n2dk​=n2d — the quadratic is in nnn, and splitting heads only re-partitions the ddd.

Why this specifically hurts: the FFN comparison

A transformer block also has a feed-forward network, whose cost is O(nd2)O(n d^2)O(nd2) — linear in nnn. Compare the two per-layer costs:

attention=O(n2d),FFN=O(nd2).\text{attention} = O(n^2 d), \qquad \text{FFN} = O(n d^2).attention=O(n2d),FFN=O(nd2).

Attention overtakes the FFN once n2d>nd2n^2 d > n d^2n2d>nd2, i.e. once n>dn > dn>d (with real constants, around n≈4dn \approx 4dn≈4d). For d=4096d = 4096d=4096, that crossover is near n≈16Kn \approx 16\text{K}n≈16K tokens: below it the model is FFN-bound and attention is a rounding error; above it, attention swamps everything and grows without bound. Long context is precisely the regime where the quadratic dominates.

Compute is only half the wall. The other half — memory — is often the one that actually stops you, and it is a separate quadratic that gets attacked separately.

Deriving the O(n²) memory

To run the softmax, a naive implementation forms the entire score matrix SSS and the attention matrix AAA in memory. Each is n×nn \times nn×n:

materialized attention matrix=n2 entries=O(n2) memory.\text{materialized attention matrix} = n^2 \ \text{entries} = O(n^2)\ \text{memory}.materialized attention matrix=n2 entries=O(n2) memory.

Put real numbers on it. At n=128Kn = 128\text{K}n=128K tokens in bf16 (2 bytes), a single n×nn \times nn×n attention matrix is

(131072)2×2 bytes≈34 GB,(131072)^2 \times 2\ \text{bytes} \approx 34\ \text{GB},(131072)2×2 bytes≈34 GB,

for one head, one layer. An H100 GPU has 80 GB total. Materializing attention at long context is not slow — it is flatly impossible, blowing past device memory before you have computed a single output. This memory wall, more than the FLOPs, is what capped context length for years.

Compute vs memory: FlashAttention changes only one of them This is the distinction that confuses people. FlashAttention (Dao et al., 2022) does not reduce the O(n2d)O(n^2 d)O(n2d) compute — it computes exact attention, same FLOPs. What it removes is the O(n2)O(n^2)O(n2) memory: by tiling the computation and running an online softmax entirely in fast on-chip SRAM, it never writes the full n×nn \times nn×n matrix to main memory, cutting the footprint to O(n)O(n)O(n) and slashing slow memory traffic. The quadratic compute remains; only the quadratic memory (and its I/O) is gone. Two walls, two fixes.

Knowing there are two quadratics, we can say exactly which one bites, and when — because inference has two phases with opposite bottlenecks.

Where it bites: prefill vs decode

Generating from an LLM has two phases, and the quadratic manifests differently in each.

Prefill — reading the prompt

The model first ingests the whole prompt of nnn tokens in one parallel pass (exactly the masked, teacher-forced forward pass). This computes the full n×nn \times nn×n attention, so prefill is compute-bound and quadratic: the time to the first output token grows like n2n^2n2. Double the prompt, quadruple the wait. This is why a 100K-token prompt has a noticeable "thinking" pause before the first word.

Decode — generating tokens

After prefill, tokens are produced one at a time. At step ttt the new token attends to all ttt previous tokens, whose keys and values are read from the KV cache (stored so they are never recomputed — causality makes this valid). Per step that is only O(t⋅d)O(t \cdot d)O(t⋅d) compute — cheap. The bottleneck moves to memory bandwidth: every step must stream the entire growing KV cache from memory, and the cache itself, of size

KV cache=2 n d L  (K and V, over L layers),\text{KV cache} = 2 \, n \, d \, L \ \ (\text{K and V, over } L \text{ layers}),KV cache=2ndL  (K and V, over L layers),

grows linearly with context and is read once per generated token — so decode is memory-bandwidth-bound, and summed over a length-nnn generation the KV traffic is again O(n2)O(n^2)O(n2). The same quadratic, wearing different clothes: prefill pays in FLOPs, decode pays in memory bandwidth and cache capacity.

The decade this one term drove

Once you see attention as an all-pairs operation with two quadratic costs, the entire "efficient attention" literature snaps into a simple taxonomy — each method is a different answer to which quadratic to attack and how. There are essentially four strategies:

  • Attend to less (sparse). Don't do all pairs — restrict each token to a subset: a local window, strided/global patterns, or learned sparsity. Cuts both quadratics to O(nn)O(n\sqrt{n})O(nn​) or O(n⋅w)O(n \cdot w)O(n⋅w). Sparse Transformer, Longformer, BigBird, sliding-window attention.
  • Approximate the all-pairs interaction (linear). Replace the softmax similarity with a kernel or low-rank factorization so the n×nn \times nn×n matrix is never needed, giving genuine O(n)O(n)O(n) attention. Linformer, Performer, linear transformers — and the modern lineage of Kimi Delta Attention.
  • Schedule it better (exact, IO-aware). Keep exact O(n2)O(n^2)O(n2) compute but kill the O(n2)O(n^2)O(n2) memory and its traffic. FlashAttention, Flash-Decoding.
  • Shrink the decode state (KV-cache reduction). Attack the memory-bound decode phase by sharing or compressing keys/values across heads. Multi-Query and Grouped-Query Attention, Multi-head Latent Attention.

And the most radical branch abandons softmax attention's all-pairs premise entirely for a recurrence with fixed-size state — state-space models (Mamba) and linear-attention RNNs — trading the quadratic for O(n)O(n)O(n) compute and an O(1)O(1)O(1) state at decode. The through-line runs right to the frontier. Kimi K3 (Moonshot's open 2.8-trillion-parameter model, 2026) is built on Kimi Delta Attention, a linear-attention mechanism in the second family above — a direct descendant of the effort to escape the very n2n^2n2 we just derived. A decade of the field's headline architectures are, at their root, footnotes to this one term.

What the escapes cost

  • Sparse and linear attention trade exactness for scale. Restricting or approximating the all-pairs interaction can miss genuine long-range dependencies; many efficient variants underperform full attention at equal size on tasks that need precise recall, which is why full (Flash) attention stayed dominant for years despite the cost.
  • FlashAttention doesn't move the asymptote. It is a constant-factor (if large) win on memory and I/O; the compute is still O(n2d)O(n^2 d)O(n2d), so at extreme context even Flash attention eventually loses to genuinely sub-quadratic methods.
  • Linear/SSM models compress history into a fixed state, which by construction cannot store unbounded detail — the recall-vs-efficiency tension is fundamental, and hybrid designs (some full-attention layers, some linear) exist precisely because neither extreme wins outright.
  • The numbers here are order-of-magnitude. Real throughput depends on kernels, hardware, quantization, and batching; the point is the scaling, not a benchmark.

Where this goes next

Two directions follow. Downward into systems: the KV cache, paged attention, continuous batching, and quantization are the engineering that makes the decode-side quadratic survivable in production. Sideways into architectures: grouped-query and latent attention, state-space hybrids, and linear-attention lines like Kimi Delta Attention are the ongoing attempt to bend the asymptote itself.

And there is a structural cousin worth flagging: the quadratic here is over the sequence (depth-1, width-n interactions). A parallel question is how information flows across depth — the residual stream — which the very next post takes up, ending at how Kimi K3's Attention Residuals apply an attention-like mechanism not across tokens but across layers.

An honesty note

The complexity derivations are exact (leading-order): attention is O(n²d) compute and O(n²) memory per layer; the FFN is O(nd²); crossover at n ≈ d (a few × d with real constants). The cost-explorer numbers are computed from those formulas with representative constants (attention ≈ 4n²d FLOPs/layer, FFN ≈ 16nd²/layer, KV cache = 2·n·d·L·2 bytes in bf16, attention matrix = n²·2 bytes); they are order-of-magnitude scaling illustrations, not benchmarked latencies. The 34 GB and 80 GB figures are arithmetic from those assumptions and an H100's advertised memory.

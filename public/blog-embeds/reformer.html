Attention is a nearest-neighbor search

Softmax is sharply peaked: for each query, nearly all the attention lands on a handful of keys, and the rest get essentially zero. Computing all n² scores just to discard 99% of them is waste. The Reformer's insight is to find each query's important keys without comparing every pair — by hashing similar vectors into the same bucket. That turns O(n²) into O(n log n).

The Sparse Transformer escaped the quadratic by attending to a fixed, hand-designed subset of positions. That works, but it assumes you know where the important connections are in advance. The Reformer (Kitaev, Kaiser & Levskaya, 2020) makes the sparsity content-based: let each query attend to whatever keys actually matter to it — and find those keys cheaply.

Start from an observation about softmax. For a query qqq, the attention weights are softmax(q⋅kj/d)\mathrm{softmax}(q \cdot k_j / \sqrt{d})softmax(q⋅kj​/d​), and because of the exponential, the weight collapses onto the keys with the largest dot products. In a long sequence, a query's attention is dominated by a few dozen near-neighbors; thousands of far-away keys receive weights so small they round to nothing. Yet standard attention dutifully computes all n2n^2n2 dot products, softmaxes them, and multiplies almost all of them by ~0. The compute went to keys that never mattered.

The one idea

Softmax attention is dominated by each query's nearest keys, so attention is really an approximate nearest-neighbor search. Exact nearest-neighbor is itself O(n2)O(n^2)O(n2) — but you can do it approximately in O(nlog⁡n)O(n \log n)O(nlogn) with locality-sensitive hashing: a hash that sends similar vectors to the same bucket, so each query only compares against the keys in its own bucket.

The whole method is: hash, sort into buckets, attend within buckets. To make it work you need a hash where "collision" means "similar."

Locality-sensitive hashing: collisions mean similarity

An ordinary hash function scatters inputs uniformly — similar inputs land in totally different buckets, which is exactly what you want for a hash table and exactly wrong here. A locality-sensitive hash does the opposite: the probability that two vectors share a bucket rises as they become more similar.

For attention we care about angular similarity (dot product ≈ cosine × magnitudes), and the standard construction is random-projection / angular LSH. Pick a random rotation, then assign each vector to a bucket by which angular sector it falls into. Two vectors separated by a small angle almost always land in the same sector; two far-apart vectors rarely do. Formally, for random hyperplanes the collision probability is a decreasing function of the angle θ\thetaθ between the vectors:

Pr⁡[ h(u)=h(v) ]  =  1−θ(u,v)π.\Pr[\,h(u) = h(v)\,] \;=\; 1 - \frac{\theta(u,v)}{\pi}.Pr[h(u)=h(v)]=1−πθ(u,v)​.

Rotate the hash below and watch: nearby points on the ring keep colliding (sharing a bucket color), while distant points split apart. Pick a query and its bucket-mates are exactly the keys it will attend to.

Angular LSH bucketing

Vectors as points on a ring (their direction is what attention scores). The hash cuts the circle into b sectors (buckets); a query attends only to keys sharing its bucket. Rotate the hash or change b and watch which keys a query can reach.

The selected query (white ring) attends to same-bucket keys. Add rounds — each round re-hashes with a new rotation and unions the neighbors — to recover keys a single unlucky hash would have missed.

Reformer also ties queries and keys (qi=kiq_i = k_iqi​=ki​, "shared-QK"), so a token's query and key always hash together and bucketing is well-defined. Tokens are then sorted by bucket and processed in equal chunks, so each attends to its bucket-mates within a chunk.

Why it is O(n log n)

After hashing into nbn_bnb​ buckets, tokens are sorted by bucket and split into chunks of a fixed size mmm. Each token attends only within its chunk (its bucket-mates), so the attention cost is

n×mwithm=O(log⁡n)    ⟹    O(nlog⁡n),n \times m \quad\text{with}\quad m = O(\log n) \;\;\Longrightarrow\;\; O(n \log n),n×mwithm=O(logn)⟹O(nlogn),

because balanced buckets over nnn items have O(log⁡n)O(\log n)O(logn) occupancy at the operating point the paper targets. The dominant remaining cost is the sort by bucket, which is also O(nlog⁡n)O(n \log n)O(nlogn) — so the whole attention step is O(nlog⁡n)O(n \log n)O(nlogn) instead of O(n2)O(n^2)O(n2). No key-pair is ever compared unless a hash already suggested they are similar.

The catch: LSH is probabilistic A single hash sometimes splits a query from a genuinely relevant key (they sit just across a sector boundary). Reformer runs multiple rounds of hashing with independent rotations and unions the buckets, so the chance of missing an important neighbour drops with each round — trading a little compute for accuracy. More rounds, better recall, higher cost.

The other half: reversible layers for memory

Cutting attention's compute to O(nlog⁡n)O(n\log n)O(nlogn) is only half of fitting long sequences on one accelerator; the other bottleneck is the memory needed to store activations for backprop, which grows with depth. Reformer borrows reversible residual layers (from RevNets): structure each layer so its input can be reconstructed from its output. Then you need not store activations for every layer — you recompute them on the fly during the backward pass, cutting activation memory from O(Nlayers)O(N_\text{layers})O(Nlayers​) to O(1)O(1)O(1). A chunked feed-forward applies the same recompute-in-pieces idea to the FFN. Together with LSH attention, this is what let Reformer train on sequences up to roughly 64K tokens on a single accelerator — where a standard transformer would exhaust memory long before.

What it cost, and why you rarely see it today

  • Approximation error. LSH attention only approximates full attention; a missed near-neighbour is a real error, and getting recall high enough needs several hashing rounds, eating into the savings.
  • Shared-QK is a constraint. Forcing queries to equal keys changes the model's expressivity, and the sort-and-chunk machinery adds implementation complexity and irregular memory access that GPUs dislike.
  • It only helps when attention is genuinely sparse. If a query truly needs broad, diffuse attention, bucketing throws away signal.
  • FlashAttention changed the economics. Once exact attention became memory-cheap and fast, the motivation to approximate at moderate lengths largely evaporated, and LSH attention saw little production adoption. Its lasting contribution is conceptual: attention as retrieval.

Where this sits in the lineage

Reformer belongs to the "attend to less" family alongside the Sparse Transformer, but where sparse attention uses fixed, hand-designed patterns, Reformer's sparsity is content-based and learned-adjacent: the hash discovers, per input, which tokens are worth comparing. That "let the data decide the sparsity" idea continues in the Routing Transformer (cluster tokens and attend within clusters) and echoes in every retrieval-augmented view of attention since. The approximate branch of the field — kernels and low-rank projections that push the cost all the way to O(n)O(n)O(n) — is the subject of the next posts on the Linformer and Performer.

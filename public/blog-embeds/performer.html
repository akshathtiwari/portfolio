Don't compute the matrix — reorder the multiply

Attention is O(n²) because the softmax couples every query with every key before you can normalize. But exp(q·k) is a kernel, and kernels factorize into a query part times a key part. Once they separate, matrix-multiply associativity lets you sum over all keys once and have every query read the result — collapsing n² to n, without ever forming the attention matrix.

The Linformer compressed the attention matrix assuming it is low-rank. The Performer (Choromanski et al., 2020) is more radical: it never forms the matrix at all. To see how, first notice what the softmax is costing us.

Strip the softmax away for a moment. Plain (QK⊤)V(QK^\top)V(QK⊤)V is a chain of matrix multiplies, and matrix multiplication is associative — you may compute it as Q(K⊤V)Q(K^\top V)Q(K⊤V) instead. And that reordering is magic: K⊤VK^\top VK⊤V is only d×dd \times dd×d (tiny, independent of nnn), so Q(K⊤V)Q(K^\top V)Q(K⊤V) costs O(nd2)O(n d^2)O(nd2) — linear in nnn. The only reason we can't do this in real attention is the softmax sitting between QK⊤QK^\topQK⊤ and VVV: it is a nonlinear function of the whole n×nn \times nn×n matrix, so you must build that matrix before you can normalize. The softmax is what blocks the reassociation.

The one idea

The softmax weight exp⁡(q⋅k)\exp(q \cdot k)exp(q⋅k) is a kernel, and any kernel can be written as a dot product of feature maps, exp⁡(q⋅k)≈φ(q)⋅φ(k)\exp(q \cdot k) \approx \varphi(q) \cdot \varphi(k)exp(q⋅k)≈φ(q)⋅φ(k). Substituting this separates the query part from the key part, and now associativity is unblocked: compute φ(K)⊤V\varphi(K)^\top Vφ(K)⊤V once — a small summary of all keys — and let every query read it. The n×nn \times nn×n matrix is never built, and attention becomes O(n)O(n)O(n).

The kernel trick, then the reorder

Suppose we can find a feature map φ:Rd→Rm\varphi : \mathbb{R}^d \to \mathbb{R}^mφ:Rd→Rm whose dot product approximates the softmax kernel: φ(q)⊤φ(k)≈exp⁡(q⋅k)\varphi(q)^\top \varphi(k) \approx \exp(q \cdot k)φ(q)⊤φ(k)≈exp(q⋅k). Then the unnormalized attention matrix factorizes,

exp⁡(QK⊤)≈φ(Q) φ(K)⊤,φ(Q)∈Rn×m, φ(K)∈Rn×m,\exp(QK^\top) \approx \varphi(Q)\,\varphi(K)^\top, \qquad \varphi(Q) \in \mathbb{R}^{n \times m},\ \varphi(K) \in \mathbb{R}^{n \times m},exp(QK⊤)≈φ(Q)φ(K)⊤,φ(Q)∈Rn×m, φ(K)∈Rn×m,

and the attention output, with normalizer DDD, becomes a chain we can reassociate:

Attn=D−1(φ(Q) φ(K)⊤)V=D−1 φ(Q)(φ(K)⊤V)⏟m×d, summed over keys once.\mathrm{Attn} = D^{-1}\big(\varphi(Q)\,\varphi(K)^\top\big)V = D^{-1}\,\varphi(Q)\underbrace{\big(\varphi(K)^\top V\big)}_{m \times d,\ \text{summed over keys once}}.Attn=D−1(φ(Q)φ(K)⊤)V=D−1φ(Q)m×d, summed over keys once(φ(K)⊤V)​​.

Read the right-hand side: first contract φ(K)⊤V\varphi(K)^\top Vφ(K)⊤V — a single pass over all nnn keys producing a small m×dm \times dm×d summary — then each query reads it with φ(Q)(⋅)\varphi(Q)(\cdot)φ(Q)(⋅). Total cost O(nmd)=O(n)O(n m d) = O(n)O(nmd)=O(n), memory O(nm+md)O(nm + md)O(nm+md) — no n×nn \times nn×n anywhere. Watch the two orderings and their cost:

FAVOR+: how to build the feature map

Everything hinges on a good φ\varphiφ. The Performer's is FAVOR+ — Fast Attention Via positive Orthogonal Random features. Draw mmm random projection vectors ω1,…,ωm∼N(0,I)\omega_1, \dots, \omega_m \sim \mathcal{N}(0, I)ω1​,…,ωm​∼N(0,I) and define

φ(x)=exp⁡ ⁣(−12∥x∥2)m[exp⁡(ω1⋅x), …, exp⁡(ωm⋅x)].\varphi(x) = \frac{\exp\!\left(-\tfrac{1}{2}\lVert x\rVert^2\right)}{\sqrt{m}}\Big[\exp(\omega_1 \cdot x),\ \dots,\ \exp(\omega_m \cdot x)\Big].φ(x)=m​exp(−21​∥x∥2)​[exp(ω1​⋅x), …, exp(ωm​⋅x)].

This is not a heuristic: one can show E[φ(q)⊤φ(k)]=exp⁡(q⋅k)\mathbb{E}\big[\varphi(q)^\top \varphi(k)\big] = \exp(q \cdot k)E[φ(q)⊤φ(k)]=exp(q⋅k) exactly — FAVOR+ is an unbiased estimator of the softmax kernel. Two design choices make it usable:

  • Positive features. The exponentials above are always >0> 0>0. An earlier idea used trigonometric (random-Fourier) features, but those take negative values, and approximating a strictly-positive kernel with sign-changing terms causes catastrophic cancellation — tiny attention weights can come out negative, destabilizing training. Positive features keep every estimated weight non-negative.
  • Orthogonal features. Making the ωi\omega_iωi​ mutually orthogonal (rather than i.i.d.) provably lowers the estimator's variance, so you get the same accuracy with fewer features mmm.

Because it is a random estimate, accuracy improves with the number of features mmm. Set the true dot product and watch FAVOR+ approximate exp⁡(q⋅k)\exp(q\cdot k)exp(q⋅k) — noisy at small mmm, converging as mmm grows.

What it costs

  • It is an approximation with variance. Unbiased is not exact: at a fixed mmm the estimate fluctuates, and sharp, high-contrast attention distributions (a query that must attend to exactly one key) are the hardest to approximate — you may need many features to represent them faithfully.
  • Causal (autoregressive) attention needs a prefix-sum. The elegant "sum over all keys once" assumes you can see all keys. For a decoder, each position may only use past keys, so the φ(K)⊤V\varphi(K)^\top Vφ(K)⊤V summary must be accumulated as a running (prefix) sum — linear, but with a sequential dependence.
  • Linear attention can lag full attention in quality on tasks needing precise recall, which — together with FlashAttention making exact attention cheap — kept softmax dominant for mainstream models even after Performer proved linearity was possible.

Where this sits in the lineage

Performer is the kernel / linear-attention branch, the sibling of Linformer's low-rank compression. Both hit O(n)O(n)O(n); both approximate. But Performer's contribution outlived the specific method: the reassociation trick — replace softmax with a feature map, contract keys-and-values into a fixed-size state, let queries read it — is linear attention, and it is the direct ancestor of every modern linear-attention design, the state-space models we will meet in Mamba, and the linear-attention core of Kimi K3. "Attention as a running summary you read from" starts here.

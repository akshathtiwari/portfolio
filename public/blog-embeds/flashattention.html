The bottleneck was never the math — it was the memory

Every sparse and linear method so far cut attention's FLOPs. FlashAttention noticed the FLOPs were never the problem: the wall-clock cost is moving the n×n attention matrix to and from slow GPU memory. Keep the computation in fast on-chip memory, never write the matrix out, and reconstruct softmax on the fly — same exact answer, same FLOPs, multiples faster.

A GPU has two very different memories. A large, slow one — HBM (high-bandwidth memory, tens of GB, a couple of TB/s) — and a tiny, blazing one — SRAM (on-chip, tens of MB, an order of magnitude faster). Arithmetic happens in SRAM; anything that doesn't fit must live in HBM and be shuttled back and forth. On modern hardware, that shuttling — not the multiply-adds — is usually what you wait for.

Now look at standard attention. It computes S=QK⊤S = QK^\topS=QK⊤ (an n×nn \times nn×n matrix), writes it to HBM, reads it back to softmax, writes the result to HBM, reads it again to multiply by VVV. The giant matrix crosses the slow HBM boundary several times. The O(n2)O(n^2)O(n2) arithmetic is fine; it's the O(n2)O(n^2)O(n2) memory traffic that dominates. Attention is memory-bound.

The one idea

Don't reduce attention's FLOPs — reduce its HBM traffic. FlashAttention (Dao et al., 2022) is IO-aware: it splits Q,K,VQ, K, VQ,K,V into blocks that fit in SRAM, computes attention block-by-block entirely on-chip, and never writes the n×nn \times nn×n matrix to HBM at all. The catch — softmax needs a whole row before it can normalize — is solved by an online softmax that builds the exact result incrementally. Same math, same output, a fraction of the memory movement.

Tiling, and the softmax problem it creates

Tiling is the easy part: cut KKK and VVV into blocks, cut QQQ into blocks, load a QQQ block and a K/VK/VK/V block into SRAM, compute that little patch of scores there, and accumulate into the output — all on-chip. The n×nn \times nn×n scores exist only transiently, block by block, and never touch HBM.

The hard part is the softmax. To normalize row iii you need its denominator ∑jexp⁡(sij)\sum_j \exp(s_{ij})∑j​exp(sij​) — a sum over all keys. But tiling only shows you a few keys at a time; you can't compute the full sum before you've seen every block. Worse, softmax must subtract the row max for numerical stability, and you don't know the max until you've seen every block either. Naively, tiling and softmax are incompatible.

The fix is a running softmax that updates its max and its sum as each block arrives, rescaling what it has so far — so the final answer is exactly the ordinary softmax.

Why this is a big win, exactly

The FLOPs are essentially unchanged — FlashAttention computes the same O(n2d)O(n^2 d)O(n2d) multiply-adds. What collapses is the HBM traffic: instead of writing and re-reading an O(n2)O(n^2)O(n2) matrix, it moves O(n)O(n)O(n) data (blocks of Q,K,VQ, K, VQ,K,V and the output), so the number of slow HBM accesses drops by a large factor tied to the SRAM size. Because attention was memory-bound, cutting the memory traffic cuts the wall-clock time — 2–4× faster in practice, and exact. See the traffic diverge:

The backward pass, and the versions

Training needs the attention matrix again for gradients — and storing the n×nn \times nn×n matrix for the backward pass would reintroduce the very O(n2)O(n^2)O(n2) memory we escaped. FlashAttention instead recomputes the needed blocks on the fly during backprop, in SRAM. Extra FLOPs, but since attention is memory-bound, those extra FLOPs are nearly free while the memory saving is decisive.

Two follow-ups worth knowing FlashAttention-2 (2023) reworked the work-partitioning across GPU warps and thread-blocks to reduce non-matmul overhead, roughly doubling throughput over v1. FlashAttention-3 (2024) exploits newer Hopper-GPU features (asynchrony and FP8) for further gains. The algorithm is the same tiling + online-softmax; the versions are about squeezing the hardware.

What it means for everything else

  • It is exact, which is why it won. Sparse and linear attention accept an approximation for asymptotic savings. FlashAttention gives the full attention result, just computed I/O-efficiently — so for the moderate-to-long contexts most models use, it removed the reason to approximate at all. Nearly every model today runs FlashAttention.
  • It doesn't change the asymptote. Compute is still O(n2d)O(n^2 d)O(n2d); at extreme context lengths, genuinely sub-quadratic methods (linear attention, SSMs) still win eventually. FlashAttention buys a large constant factor and the crucial O(n)O(n)O(n) memory, not a better exponent.
  • It's a kernel, not an architecture. You get the speedup for free without changing the model — which is exactly why it became the default rather than a design choice.

Where this sits in the lineage

FlashAttention is the reschedule-it branch of the quadratic-wall taxonomy — the one that doesn't approximate. Its arrival reshaped the whole field: by making exact attention memory-cheap and fast, it deflated the urgency behind the sparse and linear methods for mainstream lengths, and paired with grouped-query attention it defines the attention stack of essentially every modern model. Where the field still pushes past it — million-token contexts — is exactly where the constant factor stops being enough and the sub-quadratic and state-space lines take over.
